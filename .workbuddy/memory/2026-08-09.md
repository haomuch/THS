# 2026-08-09

## THS 项目：iOS 刷新时画布闪烁修复
用户在 iOS Safari 刷新页面时，三个画布（ICE 热效率 MAP / THS 杠杆图 / PSD 行星齿轮）会出现极短暂消失再重现的闪烁。确凿原因并非单点，而是多条首帧延迟叠加：

1. **ES module 串行加载瀑布**：`app.js` 在 HTML 解析阶段不会立即暴露其 4 个 import，浏览器必须等 `app.js` 解析完才能发现 `physics.js / ice-map.js / nomograph.js / psd.js`，多花一串往返。
2. **ICE MAP 背景绘制阻塞主线程**：`createIceMapBackground` 在初始化时同步执行 600×400 = 240,000 次 sub-pixel `fillRect`，Node 基准显示仅 JS 算术就 55ms，在 iOS Safari 上叠加 fillRect 调用 + 栅格化是几百毫秒级主线程阻塞（用户感知的「消失-重现」窗口就来自这里）。
3. **PSD canvas 首帧黑底**：`getContext('2d', { alpha: false })` 在首次绘制前合成成不透明黑色，必须先画一帧。
4. **画布位图尺寸 → 布局高度反馈环**：`canvas.width/height`（device pixels, round 过）会改变 intrinsic aspect ratio，`height:100%` 解析成 auto 时反过来触发 ResizeObserver，导致 ICE MAP 每次重入都重建背景（也是几百毫秒）。
5. **`will-change: transform` 在 PSD canvas 上多余**：iOS Safari 会为它单独建合成层，反而让首帧黑底更显眼。
6. **`beforeunload` 禁用 Safari bfcache**：每次刷新/返回都是冷启动，叠加前 4 个问题。
7. **Service Worker fetch handler 对每个 GET 都走 `caches.open → match` 双跳 Promise**：跨域请求也被拦截。

### 修复
- `index.html`：head 里加 5 个 `<link rel="modulepreload">` 让 5 个模块并行预取；移除 psd_canvas 的 will-change。
- `style.css`：`#ice_map_canvas` 钉死 `aspect-ratio: 280 / 200` 断反馈环；`#psd_canvas` 用固定 240px 防全局 100% 拉伸。
- `js/ice-map.js`：`createIceMapBackground` 改为按设备像素填 `ImageData` + 单次 `putImageData`，逐列/逐行常量预算。JS 算术从 240k cell 降到约 1/4 cell（仅在绘图区域）。Node 基准：旧 55ms → 新 22ms（设备端 fillRect 节省更显著）；像素差异 0.44% 全部落在色带边界 1px 采样偏移上，肉眼无差。`drawIceMap` 的 cache key 加入 canvas 尺寸，避免尺寸变了但缓存命中导致背景被拉伸。
- `js/app.js`：`init()` 末尾在 gearPaths 初始化后同步 `drawPSD` 一帧，杜绝 alpha:false 黑底闪烁；`beforeunload` 改为 `pagehide`（`!e.persisted` 才 disconnect ResizeObserver）保留 Safari bfcache；`pageshow` 仅在 bfcache 还原时重绘（`e.persisted && !animationFrameId`）。
- `service-worker.js`：cache 名升 v4；fetch 改用 `caches.match(req, { cacheName })` 单跳；跨域请求直接放行；网络重验证放进 `event.waitUntil`，不再阻塞响应。
